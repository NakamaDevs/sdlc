# Runtime integration contract

This starter does not start an AppHost. Implement the graph for the actual application languages and approved Aspire version.
Keep orchestration in this root and bind resources to explicit child checkout paths.

## Instance record

Before starting each writable instance, record its owner, task, profile, checkout paths, branches, and commits.
Assign unique routing, database, queue, worker, scheduler, cache, upload, log, and artifact namespaces.
Store local connection values in ignored configuration. Verify identity from the running application before mutations.

## Profiles and tasks

Define docs, frontend-mock, backend-contract, integrated-local, and release-check profiles as needed.
Keep the normal default stable. Require explicit profile selection for a smaller runtime.
Implement named start, status, logs, resource-restart, focused-test, integration-test, and stop tasks in mise.
Document their working directory, effects, readiness criteria, and cleanup owner. This template defines none of these application tasks yet.

## Acceptance exercise

Start one service and dependency, discover its endpoint, run a request, inspect logs, restart the resource, and stop it.
Then run two instances. Use distinct synthetic records and queue jobs to prove separation.
Stop one and verify the other remains healthy. Keep writable data on restart. Reset data only through a separate explicit task.
Block real email, payments, tax, cloud writes, and other external effects during the exercise.
Record unverified platforms and telemetry. A different port alone does not prove isolation.
