## Privacy method

The original repository was copied to a private local bundle before changes. Every remote branch head was recorded for guarded publication. Rewriting uses a separate clone and role-based author/committer metadata. Copied external snapshots are removed from all historical paths instead of redistributing extracts without their required attribution. Current maintained guides use a source catalog. No human review dates or body hashes were renewed; future snapshot controls remain unchanged.

The identity-history check rejects shallow clones and personal author or committer metadata in any ancestor. Its regressions use only synthetic identities. The structured privacy scanner, manual source review, complete reachable-object scan, and all-ref metadata audit provide complementary evidence. These checks do not prove absence of every possible identifier.

## Publication limits and recovery

Rewritten commits have new identifiers and lose old commit signatures. Existing local checkouts must be re-cloned or have only reviewed patches reapplied; merging old history would restore removed data. Preserve unrelated dirty work before that transition.

A branch rewrite does not delete GitHub PR refs, cached commit views, activity attribution, forks, other clones, or public Gist revisions. Those copies require separate authorized cleanup and, for GitHub-managed refs, support action. No public Gist publication or rewrite is part of this repository update. The private backup retains the original data for recovery and must remain access-restricted.
