# SDLC

Language-agnostic, evidence-backed SDLC guidance for people and AI agents.

This repository is the canonical, reviewable version of the guidance. The original GitHub Gist remains available as a snapshot.

## Onboarding order

1. [SDLC.md](SDLC.md) — principles, specifications, workflows, quality, and completion.
2. [HARNESS.md](HARNESS.md) — harness engineering, repository legibility, feedback loops, isolation, and Symphony.
3. [ADOPTION.md](ADOPTION.md) — intake, repository structure, templates, adoption sequence, and operating cadence.
4. [human.md](human.md) — human-in-the-loop intake, steering, editor integration, and attention protection.
5. [joy.md](joy.md) — meaningful work, autonomy, learning, focus, and team joy.
6. [burnout.md](burnout.md) — burnout risks, workload boundaries, recovery, and escalation.
7. [structure.md](structure.md) — mono-repo, multi-repo, submodules, meta, and editor automation.
8. [LINEAR.md](LINEAR.md) — issues, milestones, ownership, status, and progress.
9. [AGENT-SKILLS.md](AGENT-SKILLS.md) — research, skills, distribution, versioning, and trust.
10. [MISE.md](MISE.md) — tools, runtimes, environments, tasks, and output handling.
11. [herdr.md](herdr.md) — persistent local-first and remote-first workspaces.
12. [ASPIRE.md](ASPIRE.md) — optional orchestration, testing, previews, deployment, and observability.
13. [OLLAMA.md](OLLAMA.md) — local model serving and agent-runtime validation.
14. [TESTING.md](TESTING.md) — specifications, FIRST tests, UI evidence, and validation.
15. [SECURITY.md](SECURITY.md) — trust boundaries, secret protection, and security checks.
